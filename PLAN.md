# PLAN — Nyquist

Interactive companion for the INSAT IIA 3 MATLAB labs: *Traitement du signal* (TP1–TP4) and *Automatique linéaire échantillonnée* (every TP of the fascicule).

---

## 1. Stack, chosen on its merits

What drives the choice: the pages are mostly text, statements and derivations, with a few interactive figures. They must load fast on a phone (Lighthouse ≥ 95), print as vector PDFs, and work offline. A client-rendered single-page app with a general-purpose charting library (Plotly alone is about 1.4 MB gzip) cannot meet the performance target on a phone.

| Concern | Choice | Why (and the alternatives rejected) |
|---|---|---|
| Site generator | **Astro 5, static output** | Each TP page is pre-rendered HTML, so text and formulas paint without JavaScript (LCP). Only interactive widgets hydrate ("islands"). Rejected: an SPA (whole-page JS before first paint); Next.js static export (React runtime + whole-page hydration); SvelteKit (hydrates the whole page by default). |
| Interactive widgets | **Svelte 5 (runes)** | Compiled, very small runtime. Fine-grained reactivity, so one slider updates figure, formula, code and derivation without re-rendering the page. Scoped CSS. |
| Charts | **Own SVG plotting module** (line, stem, stairs, scatter, z-plane with unit circle, root locus, log axes, hover readout) | About 10 kB. **Vector output**, so report figures print crisply. Themed by CSS variables (dark/light). Accessible: `role="img"`, a text summary, a data-table fallback. Rejected: Plotly (size), uPlot (canvas: poor print, no CSS theming), Observable Plot/d3 (~100 kB+). |
| Math | **Temml → native MathML**: build time for static derivations, lazy-loaded for formulas that follow sliders | No math fonts to download. MathML renders natively in current Chrome, Firefox and Safari and prints well. Fallback: KaTeX in MathML-only output, decided by measurement in Phase 2. |
| Engine | **Plain TypeScript, no dependencies**, pure functions | Testable against Octave JSON; shared by the pages, Mode DS, the report and the C exporter. |
| Offline | **@vite-pwa/astro (Workbox)**: precache every page, script, `.m` file and figure | The Pyodide runtime is not precached unless the user opts in (45 MB). |
| Python "Run" (stretch) | **Pyodide 0.27.7 in a Web Worker**, loaded only on click | **Verified**: micropip installs python-control 0.10.2. c2d, poles and PI overshoot match Octave to every printed digit. Download ≈ 45 MB, so opt-in. Quirk: `step_info` needs an explicit time vector (default horizon gave Ts = NaN). |
| Report | Dedicated print route + **CSS paged media** (`@page` A4, margin boxes for page numbers, Chromium ≥ 131), then "Enregistrer en PDF" | Vector figures and real text; no PDF library in the bundle. CI also produces the default-parameter PDFs with Playwright `page.pdf()` as release artifacts. |
| Tests | **Vitest** (engine against Octave JSON), **Playwright** (375 px and 1280 px, keyboard, offline, axe-core), **Lighthouse CI** with hard budgets | |
| CI | GitHub Actions: `octave-refs` (Ubuntu + octave-control + octave-signal, same image as `docker/octave.Dockerfile`), `web` (lint, tests, build, e2e, Lighthouse), `deploy` (Pages) | |

## 2. Architecture

```
Nyquist/
├─ matlab/                     ← SOURCE OF TRUTH (the files submitted)
│  ├─ signal/tp1_….m … tp4_….m       one %% cell per handout question, French comments
│  ├─ automatique/tp3_….m, tp4_….m   (+ tp1, tp2 once the PDF arrives)
│  ├─ simulink/build_models.m        new_system / add_block / add_line for Fig 3.1, 3.2, 4.1, 4.2, 4.3
│  ├─ compat/                        Octave-only shims (stepinfo R2021a+, order, xline/yline); never needed in MATLAB
│  └─ refs/export_refs.m             runs each script in Octave and writes reference/*.json
├─ reference/*.json            ← generated by CI only (a check fails if the committed JSON is stale)
├─ python/                     ← Python twins of the cells (stretch)
├─ src/
│  ├─ engine/                  control (poly, roots, expm, tf, c2d, feedback, step, stepinfo, rlocus, Jury)
│  │                           dsp (FFT radix-2 + Bluestein, DFT, conv, circular conv, freqz, impz, quantizer)
│  │                           derive/ (step-by-step hand derivations), exercises/ (Mode DS), codegen/ (MATLAB, C)
│  ├─ content/                 handout statements (verbatim, with their source) + French explanations
│  ├─ components/              Svelte islands: Plot, Slider, Predict, Derivation, CodeCell, BlockDiagram…
│  └─ pages/                   Astro pages: /, /signal/tpN, /automatique/tpN, /ds/…, /rapport/…, /errata
├─ tests/                      engine-vs-reference, e2e, no-hard-coded-numbers lint
├─ docker/octave.Dockerfile    local mirror of the CI Octave environment
└─ tools/                      Lighthouse and phone/offline probe scripts
```

**Data flow.** For each TP there is one parameter store (Svelte runes, mirrored in the URL query and localStorage). From it, the engine produces derived results, read by every view: figure, MathML formula, derivation steps, predicted-vs-true check, MATLAB code, C export, report. **No view computes anything itself.**

**"Code follows the sliders", provable.** Parameter lines in the `.m` carry a tag, e.g. `T = 0.1;   % @param T`. The site imports the `.m` text at build time (bundled, so it works offline), splits it into `%%` cells, and replaces the tagged right-hand sides with the current slider values. **What is shown is exactly the submitted script's cell.** CI then checks the claim: for random parameter sets, it substitutes, runs the cell in Octave, and compares the results with the engine.

**"Every number from the engine", enforced.** A CI lint scans the French text of components for numeric literals outside `{expressions}` and outside verbatim handout quotes. Target: 0.

### Correctness
| Requirement | Design | Done when |
|---|---|---|
| MATLAB script = source of truth | Idiomatic MATLAB; Octave runs it in CI with `compat/` shims added to the path only under Octave; trailing local functions extracted by the harness | Every script runs to the end in CI |
| No hand-typed references | `export_refs.m` → `reference/*.json`; Vitest compares at relative tolerance 1e-9 (algebraic) or 1e-6 (simulations) | Stale-JSON check green |
| MATLAB vs Octave differences | `matlab/OCTAVE_VS_MATLAB.md`; `stepinfo` per MATLAB R2021a+ and R2020b, version named on screen | |
| Simulink PID block ≠ `pid()` | Filtered derivative modelled (N slider, default 100); ideal vs filtered compared | |
| Values the handout omits (T, K, cr, tolerance…) | Documented default + slider + Errata entry | Every E-* row of COVERAGE.md has a UI control |
| Every number from the engine | Lint above | 0 literals |

### Learning
| Requirement | Design |
|---|---|
| Predict first | On every question: a number with tolerance, a multiple choice, or "pick the curve" among engine-generated candidates; the answer is revealed after the attempt |
| Hand derivations | `engine/derive`: Z-transform with ZOH, poles, Kmax(T), Jury, static error, DFT bins and resolution, zero-padding, quantization SNR… with the current numbers |
| Mode DS | Per course, seeded random exercises (shareable `?seed=`), auto-corrected, with the full derivation as the correction |

### Deliverable
"Générer le compte rendu": cover page (name, group, date), then each question with its answer, derivation, figures at the current parameters and observations, and a MATLAB annex. A4 vector PDF.

### Industrial side
- `matlab/simulink/build_models.m`: one command per handout model.
- **"Vers le microcontrôleur"**: C(z) = K and a discretized PID (Tustin / backward Euler) exported to Arduino (AVR Timer1 ISR) and STM32 (HAL TIM callback). Difference equation, fixed sampling period, saturation, anti-windup (clamping), float or Q15 versions.
- A note on fixed-point quantization and pole displacement, computed by the engine and linked to TS TP1 1.3.
- **CI compiles the generated code** (`arduino-cli` for AVR, `arm-none-eabi-gcc` for STM32) and runs a host-gcc build of the same difference equation against the engine's output.
